# 产品构想 → 实现对照表

逐条核对 `美股低位高流动性股票观察工具_产品构想.md` 的要求是否落地，以及**具体落在哪个文件/配置项**。

## 第 1 节：项目目标

| 构想要求 | 实现 | 位置 |
|---|---|---|
| 每天筛出 3–5 只 | 主要候选上限默认 5、观察名单上限默认 5，可配 | `[output] max_main_candidates / max_watch_candidates` |
| 流动性高（美元成交额） | 20 日**平均美元成交额**门槛，用 `close × volume` 计算 | `universe.py: filter_liquidity`、`config [universe] min_avg_dollar_volume_20d` |
| 价格处于相对低位 | 距 52 周低点 + 较 52 周高点回撤 双向判定 | `scoring.py: passes_low_position_filter` |
| 有可观察的企稳迹象 | RSI 回升 / 低点抬高 / 站上均线 / 成交量改善 四项组合 | `scoring.py: score_stabilization` |
| 基本面与事件风险可见 | 风险标签体系 + SEC EDGAR 事件检查 | `risk.py: build_risk_tags`、`providers/sec_edgar.py` |
| 理由透明 | 每只股票输出 2–4 条**来自真实指标**的入选理由 + 分项得分 + 失效条件 | `scoring.py: build_reasons`、`risk.py: build_invalidation_conditions` |
| 拆成两个名单 | 低位观察组（还在跌）/ 低位企稳组（已止跌），**哪一组是主名单由 `dip_preference` 决定** | `scoring.py: classify_group / primary_group` |
| 「买跌不买涨」偏好 | 默认 `dip_preference = dip`：主名单给"位置够低且还没涨起来"的股票；已反弹的（近 1 月/3 月涨幅超限、RSI 偏高）一票排除 | `scoring.py: rebound_reason`、`[filters] max_gain_* / max_rsi_for_dip` |
| 「真正的最低点只有事后才知道」 | 报告中不出现"抄底成功"类措辞；评分明确标注"不等于上涨概率" | `report.py` 报告结尾声明 |
| 「宁可不给名单」 | 候选不足时输出"暂无符合条件的主要候选"，不做任何补位 | `report.py: render_markdown` |

## 第 2 节：美股范围

| 构想要求 | 实现 | 位置 |
|---|---|---|
| 只纳入主流交易所普通股 | 交易所白名单 + 证券类型白名单 | `[universe] exchanges / security_types` |
| ADR 可配置 | `include_adr` 开关 | `universe.py: filter_instruments` |
| 排除 OTC/ETF/权证/SPAC unit 等 | `exclude_otc` + 名称关键词黑名单 | `[universe] exclude_otc / exclude_name_keywords` |
| 默认排除股价 < US$5 | `min_price = 5.0` | `[universe] min_price` |
| 最低市值门槛 | `min_market_cap = 1e9`；市值缺失时按策略 `flag`/`exclude` 处理 | `[universe] min_market_cap / missing_market_cap_policy` |
| 门槛写在配置文件里 | 全部阈值集中在 `config/config.ini`，代码中无硬编码 | `config.py`（含范围校验） |
| 流动性以美元成交额为主 | 特征、门槛、评分、报告全部使用美元成交额 | `features.py`、`scoring.py` |
| 若数据源支持再加买卖价差 | 预留：`Features` 可扩展字段；当前数据源无价差数据，报告中不臆造 | — |

## 第 3 节：两阶段筛选

| 构想要求 | 实现 |
|---|---|
| 阶段 A 硬性过滤 | `universe.py`：交易所/类型/OTC/名称/上市状态/市值（静态）+ 股价/均额/数据陈旧度（动态） |
| 数据缺失要显示「未覆盖」 | 市值缺失 → `市值未覆盖` 标签；未启用 SEC → `重大事件未核实`；无财报日历 → `财报日期未核实` |
| 阶段 B 低位判定 | 距 52 周低点、较 52 周高点回撤、1/3/6 个月变化、相对 SPY 与行业基准、与 20/50 日均线关系 |
| 不用绝对股价判断便宜 | 报告中不出现"股价只有 8 美元所以便宜"这类表述；低位判定全部用相对区间 |
| 阶段 C 企稳证据 | RSI(14) 从低位回升、低点抬高、站回 20/50 日均线、上涨日成交额改善；明确称为"企稳证据"而非"确认反转" |
| 阶段 D 风险检查 | 财报临近、SEC 8-K/10-Q/10-K、S-1/S-3/424B 稀释、Form 25 退市、近 5/20 日极端波动、SPY 低于 200 日均线的市场环境标签 |
| 公司行动（拆股等） | 强制使用**拆股调整**后的价格序列（`Bar.adjustment`），并用调整后的成交量计算历史美元成交额；Alpha Vantage 路径按 `split coefficient` 调整成交量 |

## 第 4 节：评分系统

| 构想要求 | 实现 |
|---|---|
| 100 分制：流动性 25 / 低位 30 / 企稳 25 / 质量 20 | `scoring.py: score_all`，权重可配 |
| 分项可解释 | 每一分项都是显式线性/对数刻度，报告里逐项列出 |
| 独立风险标签，不用总分抵消 | `RiskTag`；`持续创新低`/`异常波动`/`融资稀释`/`退市` 直接降级 |
| 基本面缺失**不补满分或平均分** | `score_quality` 返回 `None` → 总分按 80 分制展示 + 「基本面覆盖不足，置信度较低」提示 |

## 第 5 节：数据源

| 构想要求 | 实现 |
|---|---|
| Alpaca（IEX 与 SIP 的区别） | `providers/alpaca.py`；`feed=iex` 时 `coverage_note` 明确写出"只覆盖 IEX，不能代表全市场成交量"，并写入报告 |
| Alpha Vantage（额度限制） | `providers/alphavantage.py`；额度耗尽时抛 `DataProviderError` 并写入 `run_log`，不静默少扫 |
| 其他供应商 | `providers/csv_provider.py`（任何导出的 CSV 都能接） |
| SEC EDGAR | `providers/sec_edgar.py`（`company_tickers.json` + `submissions`），要求 User-Agent 含联系方式，限速 ≤ 9 rps |
| 先验证覆盖再写程序 | `cli.py doctor` 会打印 provider 的覆盖说明；报告"数据与覆盖说明"一节固定包含 `coverage_note` |
| 拆股调整序列 / 不与分红口径混用 | `Bar.adjustment` 字段记录口径；`features.py` 只使用同一条序列 |
| 保留数据时间戳、来源 | `daily_bars.source/adjustment`、`corporate_events.fetched_at`、`run_log.run_at` |

## 第 6 节：每日输出格式

| 构想要求 | 实现 |
|---|---|
| 分两栏输出 | `report.py`：`A.` 主名单 / `B.` 次级观察，按构想第 6 节的报告示例排版（引用块 + 一行一字段 + 缩进子项） |
| 字段表全部覆盖 | 每只股票固定输出 11 个字段：最新行情 / 低位 / 流动性 / 技术信号 / 市场对比 / 企稳证据 / 综合分数 / 入选理由 / 风险 / 退出观察条件 / 资料来源 |
| 报告示例的排版 | 整份报告放在引用块里，每行结尾两个空格做硬换行；`> **今日结论：**` 收尾；外部只有一行免责声明。有回归测试 `test_written_files_and_required_fields` 逐个字段检查 |
| 每组 0–5 只，不够就少报 | 截断而非补齐 |
| 「暂无符合条件的主要候选」 | 明确输出该结论 |

## 第 7 节：运行时间与时区

| 构想要求 | 实现 |
|---|---|
| 以交易所日历为准，处理假日与提前收市 | `calendar_us.py`：NYSE 全部固定/浮动假日 + 观察日顺延 + 13:00 提前收市 |
| 使用 `America/New_York`，不写死 UTC 偏移 | `MARKET_TZ = ZoneInfo("America/New_York")`；`zoneinfo` 自动处理夏令时 |
| 面向新加坡用户的展示时间 | `[general] display_timezone`（默认 `Asia/Shanghai`，可改 `Asia/Singapore`） |
| 数据更新后才跑，没有新数据就跳过 | `pipeline.run_scan` 检测行情最新日期，未更新则 `skipped_reason` 并写 `run_log` |
| 关机/睡眠错过定时任务 | `scan --catch-up` / `pipeline.catch_up`：按顺序补跑缺的交易日，只取一次行情；仪表板顶部有「立即补跑」按钮 |

## 第 9 节：回测与验收

| 构想要求 | 实现 |
|---|---|
| 多年历史、覆盖涨跌震荡 | `backtest.run_backtest` 支持任意区间；`sample` 数据源覆盖下跌与反弹阶段 |
| 无未来数据泄漏 | `HistoricalView` 逐日截断 + 独立前瞻计算 + 测试逐项比对 |
| 幸存者偏差 | 无法完全消除，报告与 README 中**明确声明**，并提示接入退市名单 |
| 正确处理拆股/分红/合并/退市 | 使用调整后价格序列；退市股票若数据源提供则在阶段 A 剔除 |
| 交易成本/价差/滑点 | 回测**未扣除**，并在报告中显式标注"结果偏乐观" |
| 跟踪 5/10/20 日表现、最大不利波动、创新低比例、命中率 | `outcomes.py`：全部实现，并与 SPY 逐项对比 |
| 分开报告两个分组 | `backtest` 输出三张表：企稳组 / 未企稳组 / 全部 |
| 先模拟观察不自动下单 | 工具完全没有下单能力 |
| 验收重点是数据完整性/可复现性/理由可追溯/风险标记/自动跟踪 | `tests/` 中 95 个用例专门验证这几项（含确定性、no-lookahead、风险标签、报告字段） |

## 第 10 节：路线图

四个阶段全部落地：

| 阶段 | 落地位置 |
|---|---|
| 1 可运行原型 | `scan` / `demo`，门槛全部在 `config/config.ini` |
| 2 全市场与风险信息 | `max_symbols` 控制额度、`risk.py` 风险标签、`providers/sec_edgar.py`、`daily_*` 系列表 |
| 3 回测验证 | `backtest.py` + `outcomes.py`（含无未来数据泄漏的专项测试） |
| 4 界面与通知 | `site.py`（**静态网站，每次扫描自动导出，双击即可打开**）、`webapp.py`（本地可交互服务）、`notify.py`（邮件/IM/macOS）、`history.py`（历史名单检索与个股时间线）、`lab.py` + `[presets]`（个性化参数） |

## 第 6 节补充：报告排版

报告先给一览表再给细节：市场环境一行表格 → A/B 两组一览表 → 每只股票的指标卡（两列表格）
→ 入选理由（有序列表）→ 风险标签（级别/标签/说明三列表格）→ 退出观察条件（列表）。
不允许把多个风险标签挤成一行长段落（有回归测试
`tests/test_pipeline.py::test_markdown_is_readable_not_a_wall_of_text` 守着）。

## 第 11 节：最后的建议（默认策略）

| 建议 | 落地 |
|---|---|
| 1. 只扫描主流交易所普通股，排除 OTC/ETF/<US$5 | ✅ 默认配置即为该策略 |
| 2. 20 日均额 ≥ US$10M 且设最低市值 | ✅ 默认 `1e7` / `1e9` |
| 3. 先找接近 52 周低点且明显回撤的 | ✅ 阶段 B |
| 4. 再分「企稳」与「未企稳」，优先展示前者 | ✅ 分组 + A 区优先 |
| 5. 检查财报与重大披露，给出具体失效条件 | ✅ 风险标签 + `build_invalidation_conditions` |
| 6. 每天保存名单并跟踪真实表现 | ✅ `daily_candidates` + `candidate_outcomes` |
| **核心原则：给数据和风险，判断权交给人** | ✅ 报告结尾的免责声明与"观察名单"定位 |
